# Scalability results — full NGSIM

240 runs: 6 methods x 8 scales x 5 seeds, 60 rounds each, on the full public
NGSIM release. Generated by `experiments/runner.py --suites scale_rsu scale_pool
--noniid ngsim`; tables by `analysis/scale_tables.py`.

| File | Contents |
|---|---|
| `summary.md` | Mean +- s.d. of every metric at every scale, and DQN vs greedy/random tests |
| `summary.csv` | The same numbers in long format |
| `runs/scale_rsu/` | Per-seed records, RSU count 2 / 4 / 6 / 8 (pool 5 per RSU) |
| `runs/scale_pool/` | Per-seed records, pool 3 / 5 / 8 / 10 per RSU (2 RSUs) |

## Methods

- **Ours (dynamic) + DQN / greedy / random** — the proposed framework with the
  objective-adaptive controller (static policy, balanced weighting
  alpha = 0.2 for all five terms), differing only in the discriminator
  selector. Under this weighting the controller activates 2 critics and
  2 generator epochs per round at every scale.
- **EU-MDGAN** — early-update MD-GAN (MASCOTS 2025): every critic trains each
  round; a node transmits only when its loss beats its own best.
- **HVS-GAN** — federated GAN with DDPG vehicle scheduling (3 scheduled per round).
- **FedAvg-GAN** — HVS-GAN with uniform random scheduling.

All methods use the same data shards, backbone, mobility dropout and seeds.

## Data

Full NGSIM release (data.transportation.gov, dataset `8ect-6jqj`;
11,850,526 rows; not committed, 1.46 GB), processed by `core/ngsim.py`:

- vehicle instance = (site, vehicle id, continuous time), because NGSIM ids
  restart with every 15-minute file; duplicate records removed; tracks split at
  missing frames and resampled to 5 Hz (context window 8 frames = 1.6 s);
- RSU g is placed at site `[i-80, lankershim, us-101, peachtree][g % 4]`;
- each vehicle's shard is one (time third x road segment) cell of its RSU's
  site, 40 trajectories per vehicle at every scale (split train/test by
  vehicle, up to 1,000 test windows), one global scaler.

## Metrics

RMSE, CRPS, minADE (20 draws), PICP (nominal 90%), mode coverage; latency (s)
and compute (gradient-step units) per round, means over the final 20% of
rounds; traffic per round summed over all RSUs; rounds to RMSE <= 0.53
(about 6% below repeating the last frame, RMSE 0.566), with the fraction of
seeds that reach it.

## Notes

- Repeating the last observed frame gives RMSE 0.566 on this data.
- The epoch coordinator uses measured wall-clock time per epoch, so runs are
  not bit-for-bit reproducible under heavy parallel load; identical
  configurations (rsu2 and pool5) differ in the third decimal.
- Moving from 2 to 4 RSUs adds the US-101 and Peachtree sites, so that step
  reflects the site mix as well as scale.
